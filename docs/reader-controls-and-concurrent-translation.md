# 阅读操作与并发翻译

## 已确认

- 仓库目标名称为 collect，保持公开。仓库已由 redisread/folio 更名为 redisread/collect 并保持公开，发布前核对 Git remote、文档链接与 Cloudflare 构建连接。
- 文章列表项提供桌面右键菜单，包含标记已读或未读、收藏或取消收藏、稍后阅读、打开原文。手机提供对应的更多入口。
- 侧栏底部只显示用户名及展开指示。用户菜单收纳亮色、暗色、跟随系统、个人设置、翻译历史、安装应用和退出登录。手机阅读页保留便捷的设置入口。
- 动效轻柔克制，覆盖菜单展开、文章切换、收藏反馈、过滤后列表变化与翻译进度。常用反馈约 120–150ms，适配减少动态效果偏好。
- 阅读状态筛选采用“隐藏已读”开关。
- 打开文章即自动标记已读，支持手动改回未读。开启隐藏已读时，当前文章暂留列表，切换后移出，阅读视图保持可用。
- AI 翻译采用同篇文章默认 3 段并发，遇到限流自动降低并发并退避重试，译文按原文顺序排列。

## 过滤与恢复规则

- “隐藏已读”放在文章列表顶部，默认关闭，在当前设备记住选择。统一适用于全部文章、文件夹、订阅源、收藏和稍后阅读。
- 隐藏已读后没有可展示文章时，显示“暂无未读文章”，提供“显示全部”入口。
- 网络错误、限流等暂时性翻译错误最多自动重试 2 次。仍失败的段落保留缺口，继续处理其他段落，最后支持只重试失败段落。
- 密钥无效、余额不足等错误立即暂停整篇翻译。成功段落随账号保存，恢复时复用。
- 暂停时停止启动新段落，允许已发出的最多 3 段完成并保存，界面提示“正在保存已开始的段落”。切后台、锁屏或刷新后，回来手动继续剩余段落。

## 实现约束

- 服务端每批独立持有租约，按完成段落保存，旧的数组进度可继续读取。新进度含失败索引与降速状态，回滚代码须保留新版进度解码能力。
- 正常请求保持 55 秒超时。连接断开后给予当前批次最多 25 秒收尾，预留数据库保存时间，超时段落下次手动补译。依据 Workers 的 30 秒 waitUntil 延续上限。[Cloudflare 文档](https://developers.cloudflare.com/workers/runtime-apis/context/#waituntil)
- 开启 enable_request_signal 以接收客户端断开事件。[Request 文档](https://developers.cloudflare.com/workers/runtime-apis/request/#properties)
