# OPML 订阅导入

用户已确认执行，2026-11-08。

## 已确认

- 在个人设置增加订阅导入入口，支持电脑、手机网页及 PWA 选择 `.opml` 或 `.xml` 文件。
- 选择文件后先预览订阅源数量、文件夹数量和重复数量，用户确认后执行导入。
- 导入完成后显示新增、跳过和失败明细。
- 按订阅地址识别已有订阅并跳过，保留已有名称、文件夹和阅读记录。同一文件中的重复地址只导入一次。
- 修复现有 OPML 解析中的 XML 实体、属性顺序及嵌套目录处理问题。
- 多层目录以完整路径作为单层文件夹名称，例如“科技 / AI”。同名文件夹合并，无分类订阅进入未分类。
- 抓取成功后才保存订阅源，抓取失败的条目不导入。导入结果明确区分新增、重复跳过与抓取失败。
- 确认导入后在后台执行，关闭手机网页或 PWA 后继续处理。返回个人设置可查看任务进度和失败明细。

## 实施与验收

- 校验 OPML 结构和订阅地址，正确解析 XML 实体、属性顺序、中文名称和嵌套目录。
- 预览阶段不创建订阅源或文件夹。确认执行时再次检查重复，处理预览后新增订阅及并发导入。
- 后台导入任务及逐项结果按账号保存，队列重试避免重复创建订阅或文章。
- 抓取失败不创建订阅源，文件夹随成功导入的源按需创建。
- 文件选择、预览、确认、任务进度及结果列表适配桌面和手机窄屏，并验证刷新后恢复任务显示。
- 验证重复跳过、同站点不同订阅地址、部分失败、全部失败、任务重试及账号隔离。
- 完成后按 AGENTS.md 执行验证、PR、双轴子代理审查和合并部署。

## 已知实现约束

- 现有 `/api/opml` 接口在一次请求内串行抓取所有源，列表较大时会长时间等待。
- 当前数据库按站点地址与账号唯一约束订阅源，需要处理同站点不同订阅地址的导入兼容性与并发去重。
- 现有订阅同步队列面向已保存的订阅源。若导入在后台执行，需要先保存独立导入任务，再在抓取成功后创建订阅源，避免提前创建失败条目。

## 实现约定

- 每份列表最多 2 MB、1000 个订阅条目。文件选择支持 UTF-8 和带 BOM 的 UTF-16，解析校验 XML 完整性并拒绝 DTD。
- 预览仅保存账号所属的导入任务与条目。地址规范化保留查询参数，移除片段标识。同一文件重复地址以首次出现的分类为准。
- 原始 `POST /api/opml` 仍接收 XML 并启动导入，改为返回 HTTP 202 和任务信息。网页使用 `/preview` 和 `/jobs/:id/confirm` 分两步执行，`GET /api/opml` 保持导出用途。
- 导入消息复用 `FEED_SYNC_QUEUE`，使用 `source: opml-import` 区分。数据库待处理条目兼作待发送记录，发布队列失败后由五分钟定时任务补发，单次派发最多 200 项。
- 抓取成功后，文件夹、订阅、最多 50 篇初始文章及条目结果通过 D1 原子批次保存。条件租约防止重复处理，订阅地址唯一约束覆盖并发导入。
- 每个抓取请求和重定向目标验证公网地址，响应体限制为 5 MB。失败项显示受控错误信息。
- 个人设置显示最近 20 个导入任务，运行中的任务轮询进度，关闭页面后由后台继续。完成后刷新阅读器订阅与文章列表，保留当前选中文章。

## 验证记录

- 真实 SQLite 回归覆盖 XML 实体及多层目录、预览无订阅写入、账号隔离、同站点不同 RSS 地址、并发去重、写入失败回滚、队列发布失败补发、1000 项预览及初始 50 篇文章写入。
- 本地 Worker 与真实队列模拟器从公开 RSS 抓取，包含有效源、重复项和失效源。离开页面后处理完成，返回显示新增 1、跳过 1、失败 1，只有成功条目的文件夹与订阅落库。
- 浏览器扩展缺少文件 URL 上传权限，本地浏览器验证使用合成 File 对象触发同一文件选择处理流程。320px 无横向溢出，原生手机文件选择器与 iPhone PWA 尚待实机验收。
