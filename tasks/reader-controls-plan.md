# 阅读操作与并发翻译实施计划

依据 docs/reader-controls-and-concurrent-translation.md，用户已确认执行。

## 顺序与依赖

1. 阅读状态接口与列表筛选，验证分页和当前项暂留。
2. 文章操作菜单与账号菜单，验证焦点、触控和常驻主题应用。
3. 并发翻译服务端，兼容旧进度，按索引持久化成功与失败结果。
4. 翻译客户端暂停、恢复、补译及进度动效，依赖任务 3。
5. 仓库重命名及连接核对。
6. 完整验证、PR、双轴审查、CI、合并及原生部署验证。

## 技术决策

- 阅读状态过滤作为独立 query 参数，与原有来源筛选组合。当前选中项由服务端包含，避免偏移分页漏项。
- 保留现有翻译任务表，将 results JSON 扩展为有版本的索引状态，读取兼容旧数组。每个 step 最多调度 3 段，租约防止重复任务，成功段落独立保存。
- 使用进度版本保护重试；限流后后续批次降为串行，单段暂时性错误最多重试两次。
- 暂停停止下一批调度，保留已发出请求；服务端通过 waitUntil 维护当前批次的保存。
- 原生 popover 承载菜单，复用现有 Motion 和主题能力。

## 风险

- 过滤期间状态改变影响偏移分页，需包含选中项并在状态改变后重载当前范围。
- 译文部分成功时保留段落索引与原文顺序，失败不得被计作成功。
- 仓库更名可能影响原生构建连接，核对 GitHub 与 Cloudflare 构建结果。
- 真机后台行为与真实服务商限流须明确区分测试模拟。
