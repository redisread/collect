# OPML 可靠性实施计划

依据 [调研](../docs/opml-workers-best-practices.md)，用户已授权执行。旧阅读操作计划已完成，保留于 reader-controls-plan.md / reader-controls-todo.md（PR #14）。

## 决策
- 保留 D1 + Queues、JSON 参数、批次 1、现有表结构与用户隔离。
- Cron 两项顺序独立执行，收集错误后抛出安全摘要，避免一项失败阻断另一项。
- 日志只输出受控错误码和内部任务 ID，不输出原始异常、URL 或 XML。
- 导入使用单次抓取，暂时性失败由持久化 attempts + 队列延迟承担，最多 3 次实际抓取；普通同步保留原默认行为。
- 重试等待写入现有 leaseUntil 防止重复消息绕过退避；旧消费者写入仍需 token 守卫。
- 增加独立 workerd 本地集成测试并纳入 CI，保留快速 SQLite 回归。先检查已安装工具能力，避免整套工具链迁移。

## 顺序
1. Cron 故障隔离、结构化日志与积压摘要。
2. 抓取错误分类、导入有限延迟重试与终态语义。
3. workerd + D1/Queues 集成验证和 CI。
4. DLQ 操作说明、完整验证、PR、双轴审查、合并和原生部署核验。

## 风险与验收
- 重试乘法及重复消息：导入每次仅抓取一次、数据库总次数上限、租约保护。
- 暂时错误误判：HTTP429/408/5xx、网络超时和解析错误分别测试。
- 平台测试与 Node 不同：运行真实 workerd 绑定，生产只做已授权发布与只读核验。
- 不自动重开已有 failed 任务，避免隐式重新执行已终结操作。
